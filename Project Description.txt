## Project Name: **ClassReserve**

**ClassReserve** is a web-based classroom availability and reservation system designed for educational institutions. The main purpose of this project is to make room booking easier, faster, and more organized for students, clubs, faculty members, and administrators.

In many institutions, classroom or room booking is often done manually through phone calls, paper forms, or direct communication with office staff. This can create confusion, double bookings, time conflicts, and delays in approval. ClassReserve solves this problem by providing a digital platform where users can search for available rooms, request bookings, upload event details, and track approval status.

---

## Simple Project Description

**ClassReserve is an online system that allows users to check classroom availability and reserve rooms for classes, meetings, club events, seminars, or other academic activities.**

The system helps users find suitable rooms based on time, date, and capacity. It also allows faculty and administrators to approve or reject booking requests, detect booking conflicts automatically, and manage room maintenance schedules.

---

## What the Project Wants to Do

The main goal of this project is to create a centralized room booking platform for a campus or institution.

It wants to:

1. **Show available rooms**

   Users can search for rooms by selecting a date, time, and required capacity. The system will display rooms that are free during that time.

2. **Allow booking requests**

   Students, clubs, and faculty members can request a room for an event, class, meeting, or activity.

3. **Manage approvals**

   Faculty or admin users can approve or reject room booking requests depending on availability, purpose, and priority.

4. **Avoid booking conflicts**

   The system automatically checks if a room is already booked or blocked during the requested time.

5. **Support role-based access**

   Different users have different permissions. Students, clubs, faculty members, and admins will have separate features.

6. **Handle priority-based booking**

   Faculty bookings get higher priority than club or student bookings. For example:

```text
Faculty > Club > Students
```

7. **Manage maintenance**

   Admins can block rooms for maintenance so that those rooms cannot be booked during a specific time period.

8. **Display calendar view**

   Users can view approved events and bookings in a calendar format.

---

# Main Users of the System

## 1. Student / Club

Students or club members can use the system to search and request rooms.

They can:

* Search available rooms by date, time, and capacity
* Request room booking
* Upload event details or documents
* Check whether their request is pending, approved, or rejected
* View upcoming approved events

Example:

A club wants to organize a seminar on Saturday from 10 AM to 12 PM for 80 people. They can search rooms with capacity 80 or more, select an available room, upload event details, and submit a booking request.

---

## 2. Faculty

Faculty members can reserve rooms for academic purposes such as extra classes, exams, meetings, or presentations.

They can:

* Reserve rooms for extra classes
* View available classrooms
* Approve or reject student or club booking requests
* Manage academic room usage
* Get higher booking priority than students or clubs

Example:

A teacher wants to take an extra class from 2 PM to 4 PM. The teacher can search for an available classroom and reserve it. Since faculty have higher priority, their booking may be handled before club or student requests.

---

## 3. Admin

Admins control and manage the entire system.

They can:

* Manage all users
* Add, edit, or remove rooms
* Manage all booking requests
* Approve or reject reservations
* Detect and handle booking conflicts
* Block rooms for maintenance
* View the complete event calendar

Example:

If Room 401 is under maintenance from Monday to Wednesday, the admin can block that room for those dates. The system will not show Room 401 as available during that time.

# Key Features of the Project

## Room Availability Search

Users can search for rooms based on:

```text
Date
Start time
End time
Capacity
Room type
Building
```

The system only shows rooms that are not already booked or blocked for maintenance.

---

## Booking Request System

Users can submit booking requests by providing:

```text
Event title
Event description
Date
Start time
End time
Expected number of participants
Required room capacity
Uploaded event document
```

After submission, the request status will be:

```text
Pending
Approved
Rejected
Cancelled
```

---

## Automatic Conflict Detection

The system checks whether a selected room is already booked during the requested time.

For example, if Room 305 is already booked from 10 AM to 12 PM, another user cannot book the same room from 11 AM to 1 PM because the time overlaps.

This prevents double booking and scheduling confusion.

---

## Priority-Based Booking

The project includes a priority system where different users have different booking importance.

Priority order:

```text
1. Faculty
2. Club
3. Students
```

This means faculty requests are handled first, then club requests, then student requests.

---

## Maintenance Blocking

Admins can mark rooms as unavailable for maintenance.

For example:

```text
Room: Lab 202
Reason: Projector repair
Blocked time: 9 AM to 3 PM
```

During this time, users cannot book that room.

---

## Event Calendar View

The system has a calendar view where users can see approved bookings and upcoming events.

This helps everyone understand which rooms are being used and when.

This project is useful because it reduces manual work and makes the room reservation process more transparent.

It helps the institution by:

* Reducing double bookings
* Saving time for students, faculty, and admin staff
* Making room usage more organized
* Giving users a clear view of available rooms
* Keeping records of all booking requests
* Improving communication between users and administrators
* Making event planning easier

---

# Problem This Project Solves

Many educational institutions still manage classroom bookings manually. This creates several problems:

```text
Users do not know which rooms are available
Rooms may be booked by multiple people at the same time
Approval takes too long
Maintenance information is not clearly available
Booking records are difficult to manage
Priority between faculty, clubs, and students is not organized
```

ClassReserve solves these problems by providing one online platform for room search, booking, approval, and management.
